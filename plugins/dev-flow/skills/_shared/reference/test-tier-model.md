# テスト層モデル — 自動／手動の振り分け（dev-flow 共有リファレンス）

> **このファイルの責務は1つだけ**: 各テスト観点を「**自動テストで担保するか／手動確認に回すか**」に
> 振り分ける基準を示す。**観点そのものの網羅リスト**（あるある・性能・UI・権限・CSV・メール等）は
> dev-flow には無い。組織固有の観点は QC overlay から差し込む（[qc-overlay.md](qc-overlay.md)）。
> 本ファイルは観点を再掲せず、振り分けだけを担う。
>
> 参照するスキル／エージェント: requirement-coverage-checker（要件へ自動／手動ヒント付与）／
> test-ledger-writer（🔴 / 🟣 振り分け）／dev-test-spec（F1 分類）。

## テストの3階層（振り分けの土台）

| # | 階層 | 何を見るか | 自動化の位置づけ |
|---|---|---|---|
| ① | 機能テスト | 設計どおり機能が実現できているか | 機械が合否判定できる部分は**自動**。目視部分のみ手動 |
| ② | 運用テスト | ユーザーストーリーで誰が何をできるか | E2E 自動化できる導線は自動、実業務フロー確認は手動 |
| ③ | ユーザー視点チェック | ユーザーが思うように使えるか | 原則**手動**（主観・分かりやすさの評価） |

## 振り分けの原則

1. **判定軸は「機械が合否を判定できるか」だけ**。できる＝自動、できない＝手動。
2. **「手間だから手動」は不可**。難易度は理由にならない。
3. **自動テストの要否は最終的に人が判断する**。本ファイルの振り分けは**ヒント**であり、
   人の要否判断を置き換えない。台帳が機械的に手動送りを確定させない。

## 振り分け例（過剰手動化の防止）

| 観点 | 自動テスト向き（機能テスト） | 手動確認向き |
|---|---|---|
| 権限・アクセス制御 | 権限別の**表示／非表示の有無**・直パス遮断 | 権限画面の**レイアウトの見た目** |
| レスポンシブ | ブレークポイントでの**要素の表示／非表示・並び替えの有無** | 実機での**見た目の自然さ** |
| データ整合性 | CRUD の**結果値**の検証・0件／全削除の挙動 | 移行データの**目視突合** |
| 帳票（Word / PDF） | 出力処理の実行・ダウンロード可否 | **体裁・レイアウト崩れの目視** |
| ダッシュボード／グラフ | 集計値・描画データの検証 | 色・比率の**見た目の品質**（主観） |
| 運用テスト（ユーザーストーリー） | E2E で自動化できる導線 | 実業務フローに沿った人手確認 |
| ユーザー視点チェック | （原則対象外） | 分かりやすさ・使っていて不安や困惑を覚えないか |

> ⚠️ **権限・レスポンシブ・データ整合性を丸ごと手動にしない**。有無・結果値は自動、
> 見た目・目視部分だけが手動。自動で拾える観点を手動に流す過剰手動化への歯止めがここ。
>
> 各観点で「何をテストすべきか」の具体は組織の QC overlay 側にある。overlay が無い環境では
> 観点の網羅は各自の責任になる。**overlay が無いことを理由に振り分け基準を自作しない**
> （振り分けはこのファイルが正であり、overlay の有無に依存しない）。
