# UI/UX チェックリスト

画面の分かりやすさ・使いやすさをレビューするときの共通基準。一般に知られた UI/UX の原則
（情報設計・OOUI・フォーム設計・選択 UI・業務システムの画面設計）を、判定できる粒度の項目に落とした。
QA の評価（`qa-ux-evaluator`）、QA の探索（`qa-explorer`）、画面設計（`ui-designer`）が同じ表を見る。

## 使い方

各項目に **区分** と **強度** がある。

| 区分 | 判定できる材料 | 担当 |
|---|---|---|
| 画 | スクリーンショットを見れば判定できる | `qa-ux-evaluator` |
| 操 | 操作して初めて分かる（入力中の挙動・待ち時間・狭い幅など）。証跡に残っていなければ判定不可 | `qa-explorer` が試して事実を記録し、`qa-ux-evaluator` が判定する |
| 設 | 画面仕様（DESIGN.md）の段階で判定できる | `ui-designer` |

| 強度 | NG のときの重要度 |
|---|---|
| 必須 | Major 以上（操作を完了できないほどなら Critical） |
| 推奨 | Minor 止まり |

判定は **OK / NG / 対象外 / 判定不可** のいずれか。

- **対象外**: 画面の性質に当てはまらない項目（例: 公開サイトに業務システム用の表の項目）。理由を1行書く。DESIGN.md に「対象外項目と理由」があればそれに従う
- **判定不可**: 証跡に材料がない。推測で OK / NG にしない。`qa-ux-evaluator` は「追加探索依頼」に具体的に書く
- NG の指摘には項目 ID を付ける（例: `C2: プレースホルダーが項目名の代わりになっている`）

## A. 構造・情報設計

| ID | 区分 | 強度 | 項目 |
|---|---|---|---|
| A1 | 設 | 必須 | メニューと画面は「操作対象（名詞）」を起点にしている。登録・削除などの動詞ごとに似た画面が乱立していない |
| A2 | 設 | 必須 | 階層は3階層以内。2階層にするなら階層ごとに表現を変える（タブとサイドナビなど） |
| A3 | 画 | 必須 | 現在地が分かる（ナビの選択状態。階層が深い画面はパンくず） |
| A4 | 画 | 必須 | ラベルは日常語で簡潔、隣り合う項目と差別化されている。同じ対象に同じ言葉を使う（表記ゆれがない） |
| A5 | 設 | 推奨 | 画面パターン（一覧・詳細・編集）と操作フロー（検索から一覧、削除の位置）が全体で統一されている |
| A6 | 画 | 推奨 | 一画面の選択肢は7±2を目安にグルーピングされている |
| A7 | 設 | 推奨 | 使用頻度の高い機能に近道（最近使った項目、ショートカット）がある。クリック数の少なさ自体は目的にしない |

## B. 視覚設計・レイアウト

| ID | 区分 | 強度 | 項目 |
|---|---|---|---|
| B1 | 画 | 必須 | 近接・整列・反復: 関連要素は近く、グループ間は余白で離す。左揃えと中央揃えを混在させない。ラベル・必須マーク・入力欄の左端が揃う |
| B2 | 画 | 推奨 | 優先度の強弱がある（主要な要素が最も目立つ）。強調を色だけに頼らない（サイズ・位置・下線も使う） |
| B3 | 画 | 推奨 | 色数が絞られている（ベース・メイン・アクセントの3色が基本。ホバー等を除き5〜6色以内）。色だけで情報を区別していない |
| B4 | 画 | 必須 | 文字と背景のコントラスト比が 4.5:1 以上。操作要素が背景に溶けていない |
| B5 | 画 | 推奨 | 余白が4または8の倍数で一貫している。過剰な余白で1画面に収まらなくなっていない |
| B6 | 画 | 必須 | リンクとボタンを見た目で区別できる。影・背景色などはクリックできる要素にだけ付いている |
| B7 | 画 | 推奨 | アイコンにはラベルを併記している（一般的で自明なもの以外）。単体のアイコンはツールチップで補足している |
| B8 | 画 | 推奨 | 既存画面の刷新では、利用者が慣れた配置・色を理由なく大きく変えていない |
| B9 | 画 | 推奨 | 表: 文字列と見出しは左揃え、桁を比べる数値は右揃え（ヘッダーも揃える）。主要列の固定・ソート・絞り込みがある |
| B10 | 画 | 推奨 | 横スクロールするカードは次のカードが一部見える。文字があふれたときの扱い（折り返し・省略）が統一されている |
| B11 | 画 | 必須 | 画面崩れがない（要素の重なり、コンテナからのはみ出し、文字切れ、CSS が当たっていない素の HTML） |

## C. フォーム・入力

| ID | 区分 | 強度 | 項目 |
|---|---|---|---|
| C1 | 画 | 推奨 | 縦1列で、項目名は入力欄の上（項目数の多い表形式は左）。関連項目がグループ化されている |
| C2 | 画 | 必須 | プレースホルダーを項目名の代わりにしていない（入力を始めると消えて何の欄か分からなくなる） |
| C3 | 画 | 必須 | 必須と任意が区別できる。任意項目に「任意」と明記している（「*」だけに頼らない） |
| C4 | 画 | 推奨 | 入力欄の幅が想定する入力の長さに合っている（郵便番号・電話番号など） |
| C5 | 画 | 推奨 | 入力条件（パスワード要件など）と入力例を送信前に見せている |
| C6 | 操 | 必須 | エラーは該当箇所の近くにインライン表示される。入力の途中でリアルタイムの警告を出さない（項目単位の検証は可）。警告色は見逃されない程度に目立ち、威圧的な赤ではない |
| C7 | 操 | 必須 | エラー文が「何が・どこで・どう直すか」を平易な言葉で示す（「入力内容が不正です」だけは NG） |
| C8 | 画 | 推奨 | 入力が多いときは分割してステッパーなどで進捗を示す。デフォルト値や選択式で入力の負担を減らしている |
| C9 | 画 | 推奨 | 必須のラジオボタンに初期値がない（意図的な選択を促す）。任意なら「入力しない」の選択肢がある |

## D. 選択 UI の使い分け

| ID | 区分 | 強度 | 項目 |
|---|---|---|---|
| D1 | 画 | 必須 | 単一選択はラジオボタン、複数選択はチェックボックス（どちらも縦並び）。トグルは即時に反映される ON/OFF だけに使う（適用ボタンで反映する画面ではチェックボックス） |
| D2 | 画 | 推奨 | 選択肢が5個以下なら全て見える形、増減しうる場合や10個以上ならドロップダウン、20個を超えたら絞り込み、数十個ならグルーピング |
| D3 | 画 | 推奨 | 複数選択で選択肢が多いとき、選択内容のプレビュー（解除できる）がある |
| D4 | 画 | 推奨 | 年や日付のように短く明確な値は、自由入力か専用部品（カレンダーなど）にしている |

## E. ボタン・操作・フィードバック

| ID | 区分 | 強度 | 項目 |
|---|---|---|---|
| E1 | 画 | 必須 | ボタン文言は押した結果が分かる動詞（「戻る」より「一覧に戻る」、「はい/いいえ」より「削除する/キャンセル」） |
| E2 | 画 | 必須 | 次に進むボタンとキャンセル系のボタンでデザインを分けている。主要ボタンの位置が画面間で統一されている |
| E3 | 操 | 必須 | 操作への反応がある（ホバー・押下の変化、処理中の表示、保存・送信の完了通知） |
| E4 | 操 | 推奨 | 待ち時間は進行中であることと見込みを示す。長い処理は中断できる |
| E5 | 画 | 必須 | 取り消す手段がある（キャンセル、戻る、削除の取り消し） |
| E6 | 操 | 推奨 | モーダルは背景を暗くするなどモーダルと分かる表現で統一されている。タブはタブと分かる見た目 |
| E7 | 画 | 推奨 | クリック・タップできる範囲が、押し間違いを防げる広さである |
| E8 | 画 | 必須 | 空状態は「最初の○○を登録しましょう」のように次の行動を促す。0件・1件・複数件の表示が設計されている |
| E9 | 操 | 必須 | エラー画面や障害時の画面からヘルプや元の画面へ戻れる |

## F. 画面幅・業務画面

| ID | 区分 | 強度 | 項目 |
|---|---|---|---|
| F1 | 操 | 必須 | 画面幅を変えても破綻しない（狭い幅でメニューが省略される、表がカード形式になるなど） |
| F2 | 画 | 推奨 | 固定表示エリア（ヘッダー・サイドメニュー）は必要最小限で、操作領域を圧迫していない |
| F3 | 画 | 推奨 | 通知（未処理件数など）が目に入る位置に件数付きで出ている |
| F4 | 設 | 推奨 | ダッシュボードは、見栄えのよいグラフより業務に直結する情報と操作を優先している |
| F5 | 画 | 推奨 | 検索結果に件数などの状態が出ている。検索条件は閉じて一覧を広く使える |
| F6 | 画 | 推奨 | 業務画面のフォントは視認性の高い一般的なもの。漢字を増やしすぎていない |
