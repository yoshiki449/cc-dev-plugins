# 「コア導線」の正準定義

> E2E spec（`e2e/tests/user-stories/` `e2e/tests/functional/`）の条件付き生成を判断するための語。
> 生成してよい2条件のうち条件(2)「pytest / vitest では原理的に検証できない場合」には具体例
> （複数画面をまたぐ状態遷移・ブラウザ固有の挙動）が付いているが、条件(1)「コア導線そのものを
> 変更する場合」には定義も具体例も無かったため、ここで定義する。
>
> エージェント定義・プロンプト文字列は実行時に他ファイルを読めないため、本ファイルの定義を
> 直接参照させることはできない。したがって**本ファイルを正準**とし、消費側6箇所にインライン例
> をそのまま複製する構成にしている。定義を直したら6箇所も直すこと（下記「消費側」参照。
> `plugins/dev-flow/agents/e2e-test-generator.test.js` の `CONDITIONAL_CONSUMERS[].exampleLines`
> がドリフトを検出する）。

## 定義

コア導線とは、**それが壊れるとユーザーが目的の操作を完遂できなくなる、業務上の中心的な一連の
画面遷移**を指す。単一の画面や単一のフィールドの話ではなく、複数画面をまたいで初めて完結する
操作の筋そのものが対象になる。

## 該当例

- ログイン・決済・申請の承認/却下・権限やテナント境界をまたぐ操作

## 非該当例

「コア導線に見えるが実は当たらない」ケース。単一画面内で完結する変更や、ユニットテストで
原理的に検証できる範囲の変更はここに含まれる。

- 単純な CRUD のバリデーション追加
- 表示調整・文言変更
- 単一画面内で完結する状態変化

## 判断に迷ったときの倒し方

判断に迷ったときは、該当する（生成する）側に倒す。E2E を1本余分に生成する損失より、コア導線の
回帰を無テストのまま見逃す損失のほうが大きい。逆に倒すと、条件付き生成の既定
（既定では生成しない）と組み合わさって、コア導線の変更が無テストのまま通過し続ける
方向にリスクが偏る。
