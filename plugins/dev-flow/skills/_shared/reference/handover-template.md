# 引継書テンプレート（共通）

各 dev-* スキルが「フェーズ終了時に必ず作成する」引継書のための共通テンプレートです。

## ファイル命名規約

```
.agent/handover-YYYYMMDD-HHMM[-issue<番号>].md
```

- **新規作成必須**: 既存ファイルの上書きは禁止（履歴を残す）
- 日付・時刻は実行時のローカルタイム（`date +%Y%m%d-%H%M`）
- Issue 番号が分かる場合は末尾に `-issue<番号>` を付ける

## 共通セクション

```markdown
# 引継書 - <フェーズ名> - <YYYY-MM-DD HH:MM>

## 基本情報
- Issue: #<番号>（<URL>）
- ブランチ: <ブランチ名>
- 直前フェーズ: <plan|design|setup|implement|verify|qa|fix|ship>
- 次フェーズ: <plan|design|setup|implement|verify|qa|fix|ship>

## worktree 情報 ⚠ 必須
- **worktree 絶対パス**: `<project-folder>/worktrees/<branch-basename>/` ← 次フェーズはここに `cd` してから作業する
- **main clone 絶対パス**: `<project-folder>/repo/`
- **project folder**: `<project-folder>`

> 実装・修正フェーズ（dev-implement / dev-fix）は Step 0.5 / F0.5 でこの worktree 絶対パスと `git rev-parse --show-toplevel` の一致を照合する。ズレていたら実装コミットを作らずユーザー確認する。

## 環境情報（必要なら）
- 起動URL: http://localhost:<port>
- ログイン情報: <メール/パスワード>
- 主要サービス: <docker compose ps の概要>

## 完了事項
- <このフェーズで完了したこと>
- <生成・更新したファイル一覧>

## 未完了・申し送り事項
- <次フェーズで対応すべきこと>

## 未解決事項（承認済み保留） ⚠ 必須（0 件なら「なし」と書く）

| # | 論点 | 保留の理由 | いつ誰が決めるか | それまでの暫定案 | 決定が変わったときの影響範囲 |
|---|------|-----------|-----------------|----------------|--------------------------|

> 書けるのは **「保留すること自体をユーザーが承認した」項目だけ**。未承認の未確定事項・曖昧なままの要件を次フェーズへ送ってはならない（決めきれないなら承認を取ってからここに書く）。欄ごと省略しない（空欄は「確認していない」と区別がつかない）。

## ユーザー指示・フィードバック
- <セッション中にユーザーから受けた指示>
- <却下した案と理由>

## 次のアクション提案
- 「/clear して <次フェーズスキル名> に進めますか？」
```

## フェーズ固有セクション（追記する内容）

| フェーズ | 追加で含める内容 |
|---|---|
| plan | Issue URL、要求カード（A1.8 で合意した5項目と、解決策の妥当性チェックで選ばれなかった案）、フェーズ分割、（新規プロジェクト時）アーキテクチャ設計セクション、画面デザインフェーズ判定（UI有無・推奨可否・対象画面リスト） |
| design | claude.ai/design プロジェクトURL・ID、利用形態（新規/既存）、対象画面リスト、画面デザイン作業ステータス |
| setup | worktree 絶対パス（`<project-folder>/worktrees/<branch-basename>/`）・main clone 絶対パス（`<project-folder>/repo/`）・フラット構成からの自動移行を実施したか・コンテナ名・ポート・テストユーザー情報 |
| implement | 実装済みファイル一覧（`git diff --name-only`）、未完了Phase |
| verify | テスト結果サマリー、`.agent/evidence/<Issue番号>/` へコピーしたスクショ・動画パス、未修正バグ |
| qa | 総合判定、指摘件数、qa-report のパス、未対応指摘 |
| fix | 修正項目と対応コミット、別Issue化した項目、F1 で確定させた項目（テスト修復なら「テストと実装のどちらが正しいと決めたか」） |
| ship | PR URL、ai-memory 保存件数 |

## 注意事項

- 引継書作成は**スキップ不可**。ユーザーとのやり取りが途中に入っても必ず最後に実行する
- 引継書本文には**ユーザーが次に判断するための情報のみ**を載せる（手順の網羅は不要、詳細は元の証跡を参照）
