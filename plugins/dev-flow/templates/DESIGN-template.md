## 8. テスト方針

### ユニット
- **フレームワーク**: <例: Vitest / Jest / pytest>
- **配置規約**: <例: src/ と同階層に *.test.ts>
- **実行コマンド**: <例: npm test>

### E2E
- **フレームワーク**: Playwright
- **spec ファイル構成**:
  - `e2e/tests/security/<機能名>-security.spec.ts`（**常に生成**）
  - `e2e/tests/user-stories/<機能名>.spec.ts`（業務フロー再現・**条件付き**）
  - `e2e/tests/functional/<機能名>-functional.spec.ts`（単体検証・**条件付き**）
- **条件付きの意味**: user-stories / functional は既定では生成しない。
  (1) コア導線そのものを変更する (2) pytest / vitest では原理的に検証できない
  （複数画面をまたぐ状態遷移・ブラウザ固有の挙動）のどちらかに当たるときだけ生成し、
  理由を spec 冒頭のコメントに書く。**この設計書で「E2E を書く」と決めた項目は、
  どちらの条件に当たるかを併記すること**
- **コア導線の例**: ログイン・決済・申請の承認/却下・権限やテナント境界をまたぐ操作
- **コア導線の定義・非該当例**: dev-flow plugin の `skills/_shared/reference/core-flow.md`
- **`playwright.config.ts` 必須設定**:
  - `viewport: { width: 1920, height: 1080 }`（フルHD、ユーザーの実環境に一致）
  - `screenshot: 'on'`
  - `video: 'on'`（**レビュー用録画必須**）
  - `retries: 0`（autopilot で再試行を制御）
- **実行コマンド**: `npm run test:e2e`
