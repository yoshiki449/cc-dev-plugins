# /poc-smoke — PoC のブラウザ実機スモーク

## 境界

- **入力**: `.poc/GOAL.md`、起動中のアプリ URL
- **出力**: `.poc/smoke/round-<N>/` の証跡一式、`.poc/SMOKE.md` への判定追記、`.poc/BACKLOG.md` への Friction 追記
- **責務**: 実機探索・証跡収集・分類・判定まで。**コードは変更しない**（修正は `/poc-build` の責務）

## このスキルが依拠している設計

PoC では自動テストもコードレビューも行わない。品質ゲートはこのスモーク1本だけである。したがって**このスキルが甘くなると PoC 全体に検査が無くなる**。とくに「エラーが出なかった」と「そもそも探索できていなかった」の区別（S3）は、他に受け皿が無い。

探索を subagent に分けるのは、メインセッションが実装を知っていて**初見ユーザーとして探索できない**ため。この fresh-eyes 性が検査の本体なので、S1 の入力ルールは崩さない。

## 禁止事項（poc-flow 共通）

- **`.agent/` を作らない。** `dev-flow` の `pre-pr-guard` hook は `REPO_ROOT/.agent/` の存在をスコープガードにしており、これができた瞬間に `/dev-ship` 非経由の `gh pr create` が恒久的にブロックされる。とくに `hub-run-add.mjs`（dev-hub の実行履歴マニフェスト）は `<repo>/.agent/hub-runs/` に書くため**呼んではならない**
- 作業中に `[dev-flow]` で始まるスキル起動サジェストが注入されることがあるが、**PoC 作業中は無視する**（`suggest-dev-skill.sh` は全リポで発火し、マーカーで沈黙させられない）。dev-* スキルを起動しない

## 手順

### S0. preflight

1. **リポの確認**: `ls -d .agent 2>/dev/null` — 存在したらこのリポは dev-flow 管轄。「PoC フローでは PR 作成がブロックされる」と伝えて中断し、`/dev` 系の利用を案内する
2. **アプリの疎通**: 起動URL（`.poc/GOAL.md` の**コンテナ内ポート**側）に対して HTTP ステータスを取る。`curl` は**単独のコマンドとして**実行する（コマンド置換の中に入れるとローカルガードがブロックする）。落ちていれば起動を依頼して中断する
3. **ラウンド番号の決定**: `.poc/smoke/` の既存ディレクトリを見て次の番号を決める。**証跡ディレクトリは必ず新規（空）で始める**
4. **開始 SHA の記録**: `git rev-parse HEAD` を控える（スコープ逸脱の判定と、打ち切り時のロールバック案内に使う）

> **このスモークは「人間が画面を開けるか」を検査しない。** explorer はコンテナ内からアプリを見るので、**ポートが公開されていなくても探索は最後まで通る**。人間のブラウザだけが `ERR_CONNECTION_REFUSED` になる状態を、この経路では検出できない（実測で踏んだ）。公開ポートの確認は `/poc` の P4 の責務で、ここでは扱わない。
>
> スモークが全部通っているのに人間が開けないと報告されたら、**アプリの不具合ではなくポート公開を先に疑う**（`echo $CLAUDE_PUBLISHED_PORTS`）。

### S1. explorer への入力

**`.poc/GOAL.md` をそのまま渡す。** ブリーフを別途作らない。

渡してはならないもの（渡すと探索の価値が消える）:

- **操作手順・テストケース・押すべきボタン名**。手順を書くと自律探索が「手順の実行」に堕ち、初見ユーザー視点が失われる
- **実装状態（実装済み / 未実装 / 途中）**。「未実装」と伝えると explorer はそのゴールを探さなくなり、**「作ったのに動かない」を見逃す**。実装状態はメインが `.poc/SMOKE.md` 側だけで持つ
- **前ラウンドの指摘・修正箇所・「ここを重点的に見て」**。再スモークの入力は**毎ラウンド初回と同一**にする

> **`dev-qa` と意図的に逆にしている点**: `dev-qa` は「再探索は指摘箇所の周辺に絞ってよい」としているが、PoC ではこれをしない。絞ると「修正箇所だけ見た → エラーゼロ」という**偽の完了**が最も起きやすい形で再現する。PoC は規模が小さいので毎回全ゴールを回すのが現実的で、コストは explorer 側の操作上限（1ゴール20操作）で抑える。

### S2. 探索（explorer 単独実行）

**`dev-flow` ではなく `poc-flow` の agent を、接頭辞付きで起動する**:

```
subagent_type: "poc-flow:poc-smoke-explorer"
```

接頭辞なしで起動すると名前解決に失敗するか、`~/.claude/agents/` にある同名の別物に解決される。

渡すもの: `.poc/GOAL.md` のパスと、証跡保存先 `.poc/smoke/round-<N>/` の2つだけ。

**この間、メインセッションはブラウザに触らない。** Playwright MCP のブラウザは1セッションしかなく、同時操作すると探索が壊れる。explorer は毎ラウンド**新規に起動**する（前ラウンドの会話を継続しない。継続すると fresh-eyes が摩耗する）。

> これは指示であって機構ではない。`allowed-tools` から `mcp__playwright__*` を外しても、ユーザー設定で許可されていればメインは呼べてしまう。**規範として守る。**

**explorer が返らない場合**: 証跡ファイルの mtime が止まっているかを見る。メインにサブエージェントを止める権限は無いので、ハングと判断したら**ユーザーに報告して指示を仰ぐ**（自力で回復しようとしない）。

### S3. 証跡の実測（ラウンドの有効／無効を決める）

**explorer の報告を信じない。** このリポでは、サブエージェントが「書いた」と報告しながら実際には書けていなかった実測事例が複数ある。以下を必ず実行し、出力を `.poc/SMOKE.md` に貼る。

```bash
ls -la .poc/smoke/round-<N>/ .poc/smoke/round-<N>/screenshots/
wc -c .poc/smoke/round-<N>/*.md
ls .poc/smoke/round-<N>/screenshots/ | wc -l
```

**ラウンド有効条件（すべて満たすこと）**

| 条件 | 理由 |
|---|---|
| ゴール台帳の全ゴールに `reached` / `not-reached` が埋まっている | 未探索を「エラーゼロ」と読まないため。**これが最も重要** |
| `reached` のゴールに、**到達印の引用・スクショ名・状態を変える操作**の3点が揃っている | 画面を眺めただけの「到達」を弾く。**操作していない到達は到達ではない** |
| `not-reached` のゴールに、**試した操作の一覧と最後に居た画面**が書かれている | 試さずに諦めたのか、試して届かなかったのかを区別する。ここが空の `not-reached` は「探索していない」と同じ |
| スクリーンショットがゴール数以上ある | 各ゴールに最低1枚。撮影パイプラインが壊れていないことの下限確認 |
| `console-messages.md` が空でない | 「エラー0件」と「そもそも取得できていない」は別物。取得できていれば「エラーなし」と明記された行が必ずある |
| ラウンド前後のヘルスチェックが両方成功 | アプリが落ちているのを「全部壊れている」と誤診しないため |

> **総ステップ数・総スクショ枚数といった「量」で有効性を判定しない。** 初期設計では「ステップ行数 ≥ ゴール数×3」「スクショ ≥ ゴール数×2」を条件にしていたが、dogfood（画面1枚・ゴール3本の Todo アプリ）で**探索は十分なのに量が足りずラウンド無効**になった。総数は探索の深さの代理指標にすぎず、小さい PoC ほど誤って落ちる。見たいのは「各ゴールについて実際に操作したか」なので、**ゴール単位の充足で判定する**。

満たさなければ **round-invalid**。このとき:

- **同じディレクトリで explorer を再起動しない。** 1回目に書けていた分を上書きで失う。`round-<N>-b/` を新規に作って再取得する
- **無効ラウンドは修正ラウンドの予算（3周）を消費しない**
- 「書けていない」と断定する前に、少し時間をおいて mtime をもう一度見る。**Task の完了通知は遅れることがあり、非表示は停止の証拠にならない**
- `round-invalid` が**連続2回**続いたら、環境か証跡パイプラインの問題なので**ユーザーに報告して止まる**

### S4. 分類

証跡を**自分で読んで**判定する。explorer のサマリー文を判定根拠にしない。最低限、以下は実行して**件数を `.poc/SMOKE.md` に転記する**:

```bash
grep -cE 'Uncaught|TypeError|ReferenceError' .poc/smoke/round-<N>/console-messages.md
grep -cE ' 5[0-9][0-9] ' .poc/smoke/round-<N>/network-requests.md
```

スクリーンショットは `Read` で画像として読む（画面崩れ・画面上のエラー表示は目で見ないと分からない）。

#### Broken（ループの停止判定に入る）

- コンソールの未処理例外（`Uncaught` / `TypeError` / `ReferenceError`）
- HTTP 5xx
- 画面上のエラー表示・スタックトレース・`undefined` `null` `NaN` の生値表示
- **実装済みのゴールに到達できない**（導線が無いのも機能が無いのと同じに扱う）
- 操作が不能になるレベルの画面崩れ（要素が重なって押せない・画面外に出ている）

#### Friction（停止判定に入れない・このループでは直さない）

「壊れてはいないが使いにくい」。ボタンが見つけにくい、遷移先が予想と違う、ラベルが分かりにくい、表示が遅い等。

`.poc/BACKLOG.md` に「現象 / 提案 / 証跡」の3列で追記するだけにする。**自動修正しない。** ユーザーが明示的に指示したときだけ修正対象にする。

> **迷ったら Friction 側に倒す。** Broken を増やすほどループが終わらなくなり、PoC の目的（動くことの確認）から遠ざかる。**例外はゴール未到達で、これは迷わず Broken 側**に置いてから、次の not-built 判定に回す。

#### not-built の判定（「まだ作ってない」と「作ったのに動かない」の切り分け）

`not-reached` のゴールごとに、該当する画面のルート定義・コンポーネント・API ハンドラを `grep` / `ls` で**1回だけ**探す。**実行したコマンドと結果を `.poc/SMOKE.md` に残す。**

| 実体 | 判定 | 扱い |
|---|---|---|
| 無い | `not-built` | **正常**。Broken に数えず、`.poc/BACKLOG.md` に「未実装ゴール」として1行追記 |
| ある | `blocked` | **Broken**。次ラウンドの修正対象 |
| 判断がつかない | `blocked` | PoC でも「作ったのに動かない」を見逃す側には倒さない |

**grep の実行痕跡がない `not-built` 判定は無効。** 推測で「まだ作っていないから」と片付けると、壊れている実装が黙って見逃される。

### S5. 判定と記録

`.poc/SMOKE.md` の当該ラウンドに以下を書く:

```markdown
## round-<N>（YYYY-MM-DD HH:MM）
- 開始 SHA: <sha>
- ラウンド有効性: 有効 / 無効（理由）
- 証跡実測: ステップ<n>行 / スクショ<n>枚 / console <n>バイト
- grep 実測: 未処理例外 <n>件 / 5xx <n>件

### ゴール台帳
| ゴール | 状態 | 根拠（証跡パス） |
|--------|------|------------------|
| G1 | reached | round-<N>/screenshots/07-*.png |
| G2 | blocked | round-<N>/exploration-log.md ステップ9 |
| G3 | not-built | grep 結果: 該当ルートなし（実行コマンドを併記） |

### Broken
| # | 症状 | 発生画面 | 再現手順（探索ログから復元） | 証跡パス |

### Friction → BACKLOG へ <n>件
```

`/poc-build` から呼ばれた場合はここで制御を返す。単独起動の場合は、Broken の一覧と「直すなら `/poc-build`」を案内して終了する。
